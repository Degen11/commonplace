# Batch re-identify never got the pipeline's retry and failure reporting, and reports success when every batch fails

Confirmed by detect-code: useQuoteActions.js:212 catch swallows every non-abort batch error ('Continue with remaining batches') and line 219 shows an unconditional success toast 'Re-identified N quotes', even when every call failed. No retry and no failed-count reporting, unlike useProcessing.js:260-282 (retry once, API_ERROR with affected count) and :321 FAILED_ENTRIES. Single reIdentify (line 128) does nothing visible on an empty result array. Not documented as intentional, reachable from BulkBar Re-identify.

Evidence:
- src/hooks/useQuoteActions.js:212
- src/hooks/useQuoteActions.js:219
- src/hooks/useQuoteActions.js:128
- src/hooks/useProcessing.js:260
- src/hooks/useProcessing.js:321
- commit e12a8f5 feat: pre-warm API, partial batch retry, and integration tests

Kind: duplication.

How to fix: Extract the batch-with-retry loop from useProcessing.handleApiBatch into a shared helper that returns {results, failed}, use it in batchReIdentify, and show an error toast for the failed count instead of the unconditional success toast.
