# /api/identify proxies the raw Anthropic message envelope while every other endpoint returns its own shape, and its consumer parses model text and an Anthropic error object the server never sends

Confirmed by detect-api: All refs resolve: identify.js:164 returns the raw Anthropic body while auto-group.js:56 returns {indices} and lookup.js:214 {results}; identify.js:79 parseResults already parses the array server-side, and useProcessing.js:134-140 re-implements the same fence-strip and '[' repair. useProcessing.js:132 reads d.error.message, which no server path emits (non-2xx is thrown at :130 as 'API returned <status>', dropping the server's {error} text), whereas autoGroup at :516 reads err.error. Effect checked in utils/apiErrors.js: the daily-cap 429 is rendered as the generic 'Rate limited, wait a moment' message. Not the single-caller trap: the repo itself keeps a legacy identify request shape for cached PWA builds, so client and server do not ship in lockstep. Not documented as intentional; reachable on every AI batch. Major holds: hooks hotspot plus a shipped misleading error.
